Identity verification for Sierra Leone, built in the open.

An SDK for checking Sierra Leonean eID cards and passports: NIN validation, document OCR, face matching and NFC chip reading. Self-hosted, works offline, and there's no per-check fee.

// how it works

Five checks, each one more certain than the last.

Nearly everyone in Sierra Leone has a NIN. Sierrafy gives you the checks to use it. Run one or all five, and set your own pass, review and fail thresholds.

  1. 01
    NIN formatPOST /v1/validate-nin

    The NIN is 8 uppercase letters and digits, with no typos, stray spaces or known test values. Runs instantly, before any upload.

    ConfidenceLow
  2. 02
    Document OCRPOST /v1/ocr

    Reads the NIN, name and date of birth from the eID card or passport (including the MRZ) and checks them against what the user typed.

    ConfidenceMedium
  3. 03
    Face matchPOST /v1/face-match

    The person in the selfie is the person on the card. Nothing is stored.

    ConfidenceMedium–high
  4. 04
    Fraud signalspart of /v1/verify

    Flags edited images, photos of screens, reused NINs, expired documents and altered fonts.

    ConfidenceHigh
  5. 05
    NFC chip readPOST /v1/nfc-verify · mobile

    Reads the data stored on the card's chip and checks it against the printed card. With NCRA's root certificate, it also confirms the chip data hasn't been altered.

    ConfidenceVery high
  6. 06
    Live registry lookupphase 2 · with NCRA partnership

    Confirms the NIN is active in the national registry. This one isn't built yet: it depends on a partnership with NCRA.

    not in phase 1

note · Chip reading works now. Verifying the chip's signature needs NCRA's CSCA certificate. Until then, passive_auth_passed returns null, not a pass.

// quickstart

One call. A result you can branch on.

Run the gateway with docker compose up, then call it from JavaScript, Python or PHP. The React Native and Flutter SDKs add NFC chip reading.

  • Runs offline on your own server
  • Never stores selfies, card photos or face data
  • Consent logging built in
verify.ts 
import { Sierrafy } from '@sierrafy/sdk';

const sfy = new Sierrafy({
  apiKey:  process.env.SIERRAFY_KEY,
  baseUrl: 'https://verify.your-app.sl'
});

const result = await sfy.verify({
  nin:     'K7M2QX4P',
  idImage: cardPhoto,
  selfie:  selfiePhoto,
  options: { faceMatch: true, fraudCheck: true }
});

if (result.status === 'PASS') onboard(user);
from sierrafy import Sierrafy

sfy = Sierrafy(
    api_key  = os.environ['SIERRAFY_KEY'],
    base_url = 'https://verify.your-app.sl'
)

result = sfy.verify(
    nin      = 'K7M2QX4P',
    id_image = card_bytes,
    selfie   = selfie_bytes,
    options  = {'face_match': True}
)

if result['status'] == 'PASS':
    onboard(user)
use Sierrafy\Client;

$sfy = new Client([
    'api_key'  => getenv('SIERRAFY_KEY'),
    'base_url' => 'https://verify.your-app.sl'
]);

$result = $sfy->verify([
    'nin'      => 'K7M2QX4P',
    'id_image' => base64_encode($card),
    'selfie'   => base64_encode($selfie),
]);

if ($result['status'] === 'PASS') onboard($user);
